# Link Cord implementation and local verification (#939)

Date: October 28, 2026. Local changes on `staging`, based on
`15cd4b9c1d4cad6186eae40eca430a4ea309af8e`; no commit or deployment is implied.

## Implemented behavior

`+evolve <full-pokemon-id> Link Cord` consumes one actual bag copy for one of
the [14 approved exact mappings](../link-cord-evolution.md). Alolan form and
all four Pumpkaboo sizes are preserved. Karrablast and Shelmet each evolve
independently, without the other species. Existing trade-held routes retain
their own held item and consumption requirements.

The implementation adds supplemental item metadata and a bounded evolution
rule, reusing `EvolutionService` for ownership/placement/reservation checks,
inventory debit, save, rollback, cache restoration and replay receipts. Help,
player documentation and the PostgreSQL lifecycle CI workflow are updated.
Generated dex rows, trade transfer behavior and world stock are unchanged.

### Existing random-damage fixture failure

`pokemon/battle/tests/test_showdown_runtime_hooks.py::test_emergency_exit_queues_switch_after_crossing_half_hp`
uses an unseeded 120-power Tackle against a defender at 110 HP. The gate's
critical hit dealt 114 damage and knocked it out. The test then expected
`switch_out=True`, although `apply_damage` explicitly requires a surviving
holder before triggering Emergency Exit.

A read-only diagnostic executed that exact existing test function against both
the current checkout and an archive of unchanged baseline
`15cd4b9c1d4cad6186eae40eca430a4ea309af8e`. Seed **0** reproduced identical results
in both: **critical hit, damage 117, HP 0, no switch queued**. Database access
was explicitly refused in both diagnostic processes. This confirms the failure
exists without the Link Cord changes; no unrelated battle/test source was
edited. The two passing full-suite orders and the failed third order are
reported separately rather than treating a rerun as a clean mandatory gate.

The database suites used a new localhost-only PostgreSQL process and the
existing random-schema harness, with no game-database fallback or migrations.
Both generated schemas were removed; zero test schemas remained before the
private process was shut down. Session transport was captured, not a live socket.

## Availability and acceptance limits

Finite acquisition remains separate, as agreed in #939. The item has a
reference price but this change installs no stock, reward or automatic grant.
Hosted CI, logged-in live player acceptance, merge and deployment have not run
as part of this local implementation. Human characters and Pokemon were not
used for verification.
